# Features

Everything Mirador shows in its window, one item per part of the interface. The summary table is in the [README](../README.md#what-it-does).

## What it does

A local dashboard for your project folders:

- **Workspaces.** Each workspace is a named folder (the first one is `Dev`, on `~/Dev`) shown as a group in the sidebar. Add another one with **+ Add** (its path and an optional name), rename it inline (✎ or F2), and remove it (✕; Mirador only forgets it, no file is touched). **☰** picks which first-level folders the workspace shows; with none picked it shows all of them. The funnel filters the tree and the terminals by agent state; the terminal you are looking at (the active one) stays in view, with its folder and workspace and its tab dimmed, when its state stops matching, and hides once you activate another one.
- **Folder tree** inside each workspace, loaded level by level; the caret shows a folder's subfolders and Mirador remembers which ones are open. Hidden folders and build output (`node_modules`, `bin`, `obj`, `dist`, …) are skipped. A git icon marks git repositories; clicking it opens [lazygit](https://github.com/jesseduffield/lazygit) in that folder (it must be on your `PATH`) in a floating panel over the deck, not as a tab; quitting lazygit or its × closes the panel and ends that terminal, and Escape stays with lazygit, and a **sin memoria / no memory** tag marks folders Engram holds no memory for yet, so you can start gentle-shell there.
- **Embedded terminals.** Each folder opens either `gentle-shell` (the pi agent with the Gentle Shell package) or a plain `bash`, rendered with xterm.js. Several can run at once, as tabs or as a grid, grouped by workspace in sidebar order: each group has a header with the workspace name, its terminal count and a mark when one of them waits for an answer or finished its turn. Clicking the header collapses the group (in the grid its panes give their space to the others) or, when collapsed, expands it on its most recent terminal; selecting a workspace in the sidebar does the same, and activating a terminal from the inbox or the tracking view expands its group. Collapsed groups are remembered per window; a terminal whose workspace was removed is grouped under its workspace id. Terminals live in the server process, so reloading or closing the window does not stop them; reopening reattaches with the recent scrollback. If the server stops or dies, the agents that were open come back at its next start, each in its folder and pi session (see [Reopening agents after a restart](agents.md#reopening-agents-after-a-restart)). http(s) links in a terminal open in the browser, and a file path that names an existing file of the terminal's workspace is a link too: one click opens it in the [file editor](#file-editor).
- **gentle-shell in several folders at once.** ☑ on a workspace row turns on selection mode: each folder row gets a checkbox, and a bar under the workspace row shows how many are marked and offers **Abrir gentle-shell en N / Open gentle-shell in N**, **Guardar como proyectos del workspace / Save as workspace projects**, **Marcar los proyectos guardados / Mark the saved projects** and **Limpiar selección / Clear selection**. The saved set opens with one click from **▶ N** on the workspace row. See [Opening several agents](agents.md#opening-several-agents).
- **Daily summary** per folder from Engram: what was saved that day, grouped by type, plus the latest session summary. Each memory is laid out as labelled blocks (What / Why / Where / Learned, and the session summary headings) translated with the language switch; long fields become bullet lists and file paths show as code. Codes such as `W5`, `S3`, `T2` or `L1` and recurring terms (ODD, RDD, worktree, …) show their meaning on hover, taken from the memories on screen when one defines them, and a **Glosario / Glossary** block at the end lists them. The memory text itself stays as the agent wrote it. With no folder selected, the panel lists activity across all projects. For a container folder such as `~/Dev/web`, it lists the projects bound below it. To read a memory in Spanish, use your browser's own translator (Brave Translate, or Chrome's translate bar or right-click **Traducir a español**): memory text is marked as English, while terminals, file paths, code, folder and workspace names and the brand are marked not to translate. Mirador sends no memory text anywhere to translate it. An old config with `translateModel` still loads; the key is ignored.
- **Workspace summary and where each folder left off.** Moved to [Where it left off](attention.md#where-it-left-off).
- **Where it left off in plain mode.** Without gentle-shell, pi or Engram (`mode: plain`), selecting a folder shows, in the panel's **Dónde quedó / Where it left off** view, its git branch (or the detached HEAD's short sha), last commit, changed files (counted, up to 50 listed, each with its kind: modified, untracked, renamed…) and five most recent commits, and its `NOTES.md` as plain text (only that exact name at the folder's root, up to 16 KB). A folder that is not a git repository, or a machine without git, shows "Not available" instead. Git runs read-only and never above the workspace root; no Engram route is called. Details in [How Mirador is built](how-it-works.md#how-it-works).
- **Changes.** In both modes, the panel's **Cambios / Changes** view shows a selected folder's (or workspace's) changes against its last commit, staged and unstaged together: a stat line ("3 files changed: +12 −4"), each file with its added and removed lines (or *binary*), and each file's diff coloured by line (added, removed, hunk header, file header), then the untracked files by name only. It only reads the repository: no index refresh, no hooks, filters, textconv or external diff programs. Very large diffs are cut (512 KB in all, 64 KB per file) and say so; a folder that is not a repository, a repository without commits, or a machine without git shows "Not available". Details in [How Mirador is built](how-it-works.md#how-it-works).
- **Adjustable columns.** Drag the edge between the sidebar and the terminals, or between the terminals and the panel, to resize them (arrow keys on the focused edge, Shift for bigger steps; double-click resets). The selected folder shows its buttons on a second line, so its name is never hidden. Widths are remembered per window.
- **Narrow windows.** Under 1280 px the panel leaves its column, and under 960 px the sidebar too; its topbar button opens it as a sheet over the terminals, and one click on the other button swaps sheets. While a sheet is open the rest of the window is inert and Tab stays inside it; its hide button, a click on the dimmed terminals or Esc closes it and puts the focus back on the button that opened it. In a wide window the same topbar button brings back a hidden column. A narrow terminals area stacks the grid panes in one column that scrolls. Below 720 × 560 px the page scrolls instead of squeezing further, and past 2560 px wide it stays centered.
- **Tracking view.** The **Desarrollo | Seguimiento** (Development | Tracking) switch in the top bar swaps the workspace layout for a read-only overview: how many projects are advancing today, how many agents are running and how many wait for your answer or finished their turn, the agent terminals Mirador runs sorted by what they need from you (see [Tracking view](attention.md#tracking-view)), and the Engram projects with activity today. Agents sit in lanes by what they need from you (needs you, to review, working, what Mirador did), each lane with its own scroll, and the charts, projects and memory health sit in a collapsible dock. The night shift lives in the view's strip (its on/off switch is under **Ajustes**): see what is waiting for you, read what Mirador did overnight, mark each move Right or Wrong so it learns, and open its settings to connect your own Telegram bot. Mirador's night moves are reviewed by a judge, and you can mark them right or wrong (saved to Engram for the decider). Pending items and the morning summary reach you on the desktop and, optionally, on your own Telegram bot. The night shift can follow a schedule (days, start and end in your time zone); before it starts, a bedtime reminder lists what each agent still has to do and lets you leave an execution note per agent or workspace, delivered when the night begins.
- **Resource profiles.** In the night panel, **Perfil de recursos / Resource profile** (a folded part of Shift settings; its comparison table is under «Qué fija cada perfil») picks Ahorro, Equilibrado (default) or Potencia: Claude calls per jornada (60 / 150 / 400; a jornada ends when the night shift ends, 06:00 without a schedule, and an autopilot switched on by hand has no cap, only one notice when it passes the limit) and **Mejorar con IA** runs per day (100 / 300 / 1000), the night decider's model (Haiku / Sonnet / Opus 5.5), whether the judge reviews every move or only doubtful ones, Claude processes at once (1 / 2 / 4), the Engram cache (60 / 20 / 10 s) and the tracking refresh (30 / 15 / 10 s). It applies at once without a restart and never changes a safety rule. A meter shows the calls used tonight and the **Mejorar con IA** runs used today; when a budget runs out, Mirador leaves decisions for you (or refuses **Mejorar con IA** until tomorrow) and tells you once. Every Claude call is logged without its text in `~/.local/state/mirador/telemetry/calls.jsonl`. The config keys `nightModel`, `maxConcurrent`, `engramCacheMs` and `nightBudget` override the profile.

Until you choose a language, the interface follows the browser's (Spanish for `es-*`, English otherwise); pick EN or ES under **Ajustes / Settings** in the top bar to switch, and Mirador remembers that choice. The same sheet holds the **Piloto automático / Autopilot** switch (a chip in the top bar says when it is on), **Terminales / Terminals** (Pestañas / Cuadrícula) and **Tema / Theme** (Claro, Oscuro, Gentleman); Esc or a click outside closes it. The top bar keeps only the brand, the Desarrollo | Seguimiento switch and the free memory.

## File editor

**Archivos / Files** on a folder row (📄 on a workspace row) opens that folder's files, dotenv files first, in a plain-text editor: Ctrl+S or ⌘S saves, Esc closes and asks first when something is unsaved. When a folder has `.env.example` but no `.env`, one click creates `.env` from it (never over an existing `.env`). Each save carries the version it opened: if an agent changed the file meanwhile, Mirador asks to reload it or overwrite it. Only regular UTF-8 text files of up to 1 MiB inside the workspace root open (symlinks that leave the root do not); a save is atomic and keeps the file mode. Details in [docs/extending.md](extending.md#w5-file-editor-built).

**File links in the terminals.** In any terminal's output (gentle-shell or any other program), a path that names an existing file inside that terminal's workspace is underlined on hover; clicking it opens the editor on that file, in the folder that holds it. The path can be absolute, or relative to the folder the terminal was opened in (`./x`, `../x`, `a/b.ts`, or a bare name with an extension such as `notes.md` or a dotfile such as `.env`), and can end in `:line` or `:line:col`, which is not part of the path; quotes, backticks, brackets and trailing punctuation around it are left out too. A path outside the workspace (also through `..`), a folder, a file that does not exist and a plain word are never links, and http(s) URLs keep their own links. Mirador checks that the file exists by listing its folder, at most once every 30 seconds per folder. A relative path is read from the folder the terminal was opened in, even after a `cd`.
